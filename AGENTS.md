# AGENTS.md

## Layout

- The Next.js app lives in `sources/`. Run **every** npm / Prisma / Docker command from `sources/`, never the workspace root: tests and `scripts/with-db.mjs` call `process.loadEnvFile(".env")` relative to cwd, so from the root they silently miss the env file.
- `sources/AGENTS.md` is generated by `next dev`. Do not edit or delete it — it reappears as an uncommitted change. Read the bundled docs it points to (`sources/node_modules/next/dist/docs/`) before writing Next.js code.
- Stale doc: `chuc-nang-du-an.md` (root) describes an abandoned Vite/localStorage plan — ignore it. `sources/README.md` is current for env vars, API shapes and business rules.
- No CI workflows exist. Verification is local only.

## Commands (from `sources/`)

```sh
npm install            # postinstall runs prisma generate
npm run dev
npm run lint           # bare `eslint`, ESLint 9 flat config
npx tsc --noEmit
npm run build
npm test
```

`npm test` runs the four suites with `--test-concurrency=1` because they share one MySQL test database. Do not parallelize them.

## Content vs. data (read this first)

- **Marketing content is fixture-driven.** `app/(site)/**` reads tours, posts, destinations, cuisines, FAQs and brand info from `lib/fixtures/*`. Editing MySQL changes nothing there — edit the fixture. This is deliberate: it keeps the public pages prerenderable.
- **Booking data is DB-driven.** `/dat-tour` and `/tour/[slug]` load tours and departures from MySQL via `server/catalog/*`, so the `departureId` sent to `POST /api/orders` always exists. `/tour/[slug]` is therefore `ƒ` (dynamic), not prerendered.
- **Every customer flow is wired end to end.** `lib/booking/submit.ts`, `lib/orders/client.ts` and `lib/contact/client.ts` call `/api/orders`, `/api/orders/lookup|cancel` and `/api/contact` through `lib/api/client.ts`. No mock adapters remain — a booking made in the browser is a real row in `orders`.
- **Prisma lives in `server/**`** (plus the legacy `lib/auth/session.ts`). `app/` and `components/` must never import `@/lib/prisma`; go through a `server/<domain>/` service.
- `lib/api/client.ts#apiRequest` accepts `baseUrl` and `fetchImpl` — use them to unit-test adapters in Node, whose `fetch` cannot resolve relative URLs.

## Where logic belongs

- Capacity, pricing, state transitions and audit go in `server/booking/`. Route handlers in `app/api/` and server actions in `app/admin/(dashboard)/**/actions.ts` are thin wrappers — keep them thin.
- Other domains: `server/catalog/` (public tours + departures), `server/contact/` (contact messages), `server/settings/` (settings read + site-settings merge). `server/errors.ts#AppError` is the shared error type; `BookingError` only adds a narrower `code` union.
- Booking settings (`holdHours`, `cancelCutoffDays`, `maxGuestsPerOrder`, `minDaysAhead`) come from the `settings` table via `server/settings/get-site-settings.ts`. Never hardcode these numbers in a component — the server would disagree.
- Admin UI is server components + server actions calling `server/booking/admin-queries.ts` / `admin-update-order.ts` directly. The `/api/admin/orders*` routes are a parallel, UI-less path. `app/admin/login/actions.ts` and `app/api/admin/login/route.ts` are duplicate login implementations (page vs. tests) — a fix in one usually needs the other.

## Next.js 16 specifics

- `cacheComponents: true` and `partialPrefetching: true` are on. Route handlers must **not** export `runtime` or `dynamic` (the build fails). Request-time GETs call `await connection()` from `next/server`.
- The admin guard is `sources/proxy.ts` (Next 16's rename of `middleware.ts`). It only matches `/admin` pages; API routes authenticate themselves via `requireAdminApi()`.
- Pages that read `cookies()`/`searchParams` declare `export const instant = false` (see `app/admin/layout.tsx`, `app/(site)/tour/[slug]/page.tsx`).

## Tests

- `scripts/tests/unit/*.test.ts` are pure logic and need neither database nor `.env` — they are the only suites that run on a fresh clone:
  ```sh
  npm run test:unit
  ```
- `booking`, `admin` and `jobs` are integration suites and throw immediately without `TEST_DATABASE_URL`, plus a migrated and seeded test DB:
  ```sh
  npm run db:migrate:test
  npm run db:seed:test
  ```
- The DB suites delete orders and mutate departures/admins. Never point `TEST_DATABASE_URL` at dev or production data.
- They overwrite `process.env.DATABASE_URL` with `TEST_DATABASE_URL` via `scripts/tests/helpers/env.ts`, so `npm test` can never hit production even if `DATABASE_URL` is.
- `test:jobs` runs plain `node --test` (no `--import tsx`) so it cannot import TS helpers; it keeps its own env block. All other suites import `./helpers/env` first.
- **`--test-concurrency=1` is mandatory for any command that runs more than one DB suite.** They share one MySQL database, and `jobs.test.mjs` asserts global counts — parallel runs see intermediate state and fail. This is why every script sets the flag.
- In `.mts` test files, import app modules with `const { x } = await import("@/…")`. Static named imports from a `.ts` module fail under tsx (`does not provide an export named …`) because tsx emits CJS for `.ts`.
- Factories: `scripts/tests/helpers/factories.ts` — import via `@/scripts/tests/helpers/factories`. `cleanupTour` deletes reviews → orders → tour (Order does not cascade from Tour).
- Coverage gates (thresholds ratchet upward, never down): `npm run test:coverage:unit` (pure modules) and `npm run test:coverage` (backend).
- `scripts/tests/contract.test.mts` pins the public DTO: its key list is typed `Record<keyof PublicOrder, true>`, so adding a field to `lib/contracts/order.ts` without updating the test breaks `tsc`. Two real drift bugs were caught this way (`pricing.currency` literal, nullable `cancellation.policy`).
- One focused case:
  ```sh
  node --import tsx --test --test-name-pattern="<pattern>" scripts/tests/booking.test.mts
  ```

## Database safety

- Unscoped Prisma and the plain `db:*` scripts use `DATABASE_URL`, which points at the Aiven **production** MySQL. Prefer `db:*:dev` / `db:*:test`; their `scripts/with-db.mjs` wrapper overrides `DATABASE_URL` (it works because `loadEnvFile` does not overwrite existing vars).
- `npm run jobs:expire` mutates data (`-- --dry-run` to preview); `jobs:reconcile` only reports unless given `-- --fix`.
- Seed is idempotent and refuses to run when `NODE_ENV=production` unless `SEED_ALLOW_PROD=1`. Re-seeding never resets an existing admin password, and only overwrites `settings` when `SEED_FORCE_SETTINGS=1`.

## Booking invariants (test-enforced)

- Infants consume a seat but are free; the holiday surcharge applies to adults + children only.
- Prices never come from the client — the server snapshots `unit_price_adult`, `unit_price_child`, `surcharge`, `total_amount`.
- Capacity is claimed in one atomic `UPDATE ... WHERE seats_taken + n <= capacity_total`; the affected-row count is the check.
- `orders.client_request_id` is unique, so a retried create returns the existing order and takes no extra seats.
- Date cutoffs use `todayVN()` from `lib/time.ts` (Vietnam time), never server-local or UTC calendar dates.
